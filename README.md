# Ccutu

앱 이름(홈 화면·앱 안 제목)은 **모투**. 저장소·프로젝트·번들 ID는 그대로 Ccutu다.

끄투온라인(https://github.com/JJoriping/KKuTu)의 한국어 끝말잇기를 iOS로 옮긴 앱.
근처 기기끼리(Network framework) 또는 Game Center 친구 초대로 인터넷에서 플레이한다. 로봇과의 연습도 제공한다.

홈의 개인전·팀전·연습전은 노랑·파랑·빨강 채움 버튼으로 나란히 배치한다.
개인전·팀전에서 근처 플레이 / 인터넷 플레이를 고른다. 근처 방은 6자리 방 코드로 입장하고, 인터넷 플레이는 Game Center 친구 초대를 사용한다. 연습전은 로봇 난이도·규칙을 고른다.
팀전은 원작처럼 2~4개 팀의 인원수가 같아야 시작하며, 팀을 번갈아 진행하고 결과는 팀원 점수 합계로 매긴다.
대기실에서 자신의 팀을 고를 수 있고, 방장은 로봇의 팀도 바꿀 수 있다. 플레이어 초상은 원작 기본 모레미를 사용한다.

플레이·커스터마이징 탭을 제공한다. 닉네임 설정은 커스터마이징으로 옮겼고, 기본 닉네임을 한 번도 바꾸지 않은 경우에만 탭바 위에 변경 안내를 띄운다.
끝까지 진행한 개인전·팀전에서 단독 승리하면 원작 모레미 꾸미기 29종을 하나씩 순서대로 해금한다. 팀전은 승리 팀원 모두에게 각각 지급하며 연습·무승부·중도 종료·내기 게임은 제외한다.
같은 대전 ID에는 한 번만 보상하며, 해금·장착·승리 기록은 기기에 저장한다. 모두 모은 뒤에는 승리 횟수만 증가한다. 선택한 머리·눈·입은 입장 메시지와 게임 스냅샷으로 공유한다.

## 빌드
1. `brew install xcodegen` (설치돼 있음)
2. `xcodegen generate` → `Ccutu.xcodeproj` 생성 (git에 넣지 않음)
3. Xcode에서 `Ccutu` 스킴 실행. 코어 테스트: `cd KkutuCore && swift test`

## 멀티플레이 연결
- 근처 플레이: `NWBrowser`·`NWListener`의 Bonjour 탐색과 peer-to-peer Wi-Fi를 사용한다. `_motu-v2._tcp`를 선언하고, 방마다 무작위 6자리 코드로 TLS PSK 연결을 맺는다. 코드는 탐색 정보에 싣지 않는다. TCP 메시지는 4바이트 길이 헤더로 분리하고 최대 1 MiB로 제한한다. 경주 프레임은 전송 대기 중 최신 하나로 합친다.
- 인터넷 플레이: `GKLocalPlayer` 초기화 → Apple 친구 초대 화면 → `GKMatch` 연결 → 앱의 대기실 순서다. 초대를 받은 앱은 `GKLocalPlayerListener`로 수락을 처리한다. 개인전·팀전은 서로 다른 매치 그룹으로 나눈다. 초기 방장은 Game Center 플레이어 ID 정렬로 고르고, 이후 방장 이탈은 기존 입장 순서로 승계한다. 두 경로 모두 같은 `HostCore`와 꾸미기·팀·게임 메시지를 사용한다.
- `Ccutu.entitlements`와 `project.yml`에 Game Center capability를 선언한다. 인터넷 연결에는 각 기기의 Game Center 로그인과 같은 앱 ID/호환 버전이 필요하다. 배포용 앱과 별도 개발 앱은 Game Center에서 서로 다른 앱이다.
- Apple Developer에서 해당 App ID의 Game Center와 프로비저닝을 활성화하고, 해당 앱의 App Store Connect Game Center 구성을 준비해야 한다. 인증·초대 실패는 앱 안에 표시한다. 서버를 직접 운영하지 않는다.
- iOS 27 GameKit은 끝난 대전의 연결을 치우지 않아 같은 실행에서 두 번째 인터넷 대전을 맺으면 GameKitServices 안에서 튕긴다(FB24789094, 빌드 10 실기기에서 재현). 그래서 iOS 27 이상에서는 한 실행에 인터넷 대전 한 번만 열고, 다음 초대·수락은 앱 재시작 안내로 막는다. 같은 방에서 판을 이어 하는 건 매치를 그대로 쓰므로 괜찮다. 애플이 고친 iOS가 나오면 `GameCenterService.oneMatchPerLaunch`의 조건을 그 버전 미만으로 좁힌다.
- 그래서 인터넷 방에서는 나갈 때 한 번 묻고, 방장은 대기실의 "친구 더 초대"로 지금 매치에 사람을 더한다(`GKMatchmakerViewController.addPlayers(to:)`, 새 매치가 아님). 늦게 들어온 사람은 기존 사람들이 인사에 실어 보낸 방장을 따른다(`HostElection`, 인사 버전 3 — 2와는 섞이지 않는다). 빈 매치에 사람을 더하는 것과 iOS 27 크래시를 피하는지는 실기기 두 대로 확인해야 한다.
- 기존 MultipeerConnectivity 빌드와 근처 방을 함께 사용할 수 없다. 참가자 모두 새 버전을 사용해야 한다.
- 이번 연결 교체는 코어 단위 검사·기기용 빌드로 확인한다. 사용자의 요청에 따라 앱 실행·두 기기 연결·실제 인터넷 초대 검증은 하지 않는다. 아래의 과거 MPC 실행 기록은 새 전송 경로의 검증 근거가 아니다.
- 근처 플레이 실행 확인(2026-10-18, 17e 방장 + 17 Pro 참가자 시뮬레이터): 처음엔 방이 열리지 않고 입장도 안 됐다. 두 가지를 고친 뒤 방 코드 입장 → 준비·설정 반영 → 마블 룰렛 단어 입력이 두 폰에 반영 → 경주 장면·순위표가 두 폰에서 같게 움직이는 것까지 확인했다.
  - 방장: 연결 대기(`NWListener`)가 준비되기 전에 광고 정보를 다시 넣으면 Bonjour 등록이 끊겨 -65563(ServiceNotRunning)으로 실패했다. 준비 뒤에만 광고를 갱신한다.
  - 참가자: 방 코드 입력창이 닫히며 방 찾기 화면의 `onAppear`가 다시 불려 `startBrowsing()`이 맺던 연결을 끊었다(방장 쪽 -9816). 입장 중이거나 방에 있으면 검색을 다시 시작하지 않는다.
  - 인터넷(Game Center) 플레이와 실기기 두 대 연결은 아직 확인하지 않았다.
